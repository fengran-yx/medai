# 医院落地说明 · 从质控工具到可追责的临床治理流程

> 对应代码：`server/src/qc/review.js`、`server/src/qc/tasks.js`、`server/src/audit/`、`server/src/routes/reviews.js`、`server/src/routes/tasks.js`
> 前端：`web/src/views/WorkbenchView.vue`、`RecordDetailView.vue`、`LogsView.vue`

## 1. 这版解决了什么

医院不会接受“AI 打个分就直接算数”。要让 AI 质控真正进入病案管理流程，至少需要四条链：

1. **责任链**：AI 只做初筛，质控医师确认/改判，最终分由人负责；
2. **整改链**：不通过要有承办人、科室、截止时间，能督办、能关闭；
3. **证据链**：谁在什么时间改了什么，日志要能自证没被篡改；
4. **账号链**：弱口令、暴力破解、离职账号、旧 token 都要能兜底。

对应四个能力模块：

| 模块 | 入口 | 角色 |
| --- | --- | --- |
| 待复核队列 | `/workbench` → 待复核 | 质控医师、管理员 |
| 人工复核/改判 | 工作台或病历详情 | 质控医师、管理员 |
| 整改任务 | `/workbench` → 整改任务 | 质控/管理员看全量，临床医师看本人 |
| 审计链校验 | `/logs` | 质控医师、管理员 |

## 2. 质控状态机

```
AI 质控
  ├─ review_status = pending, final_score = null
  ├─ 分数 <80 → 自动建整改任务（open，due = now + 3d）
  └─ 分数 ≥80 → 关闭该病历 open/submitted 任务（passed）

质控医师复核
  ├─ confirm  → final_score = AI 分
  └─ override → final_score = 人工分
        ├─ final ≥80 → medical_records.status = qc_passed，任务 passed
        └─ final <80 → status = qc_failed，任务保持/新建

临床医师整改后重新质控
  ├─ 生成新报告（pending）与新版本快照
  ├─ 旧任务 report_id 更新
  └─ 新分 ≥80 → 任务自动关闭
```

关键约束：

- 只能复核**该病历最新一次**报告，避免用旧报告改当前状态；
- 复核/改判写审计日志，记录 AI 分 → 最终分；
- 报告打印页展示最终分、复核人、复核意见；未复核时明确标注“待复核”；
- 历史报告在迁移时统一标记为已复核，避免升级后把旧数据全部塞进待复核队列。

## 3. 整改任务

字段：`record_id / report_id / doctor_id / dept_id / status / due_at / note / closed_at`。

- 建单：AI 分 <80，且该病历没有 `open/submitted` 任务；
- 更新：重新质控仍不通过，只更新 `report_id`，不重复建单、不自动延长截止时间；
- 关闭：复评 ≥80 自动 `passed`；质控科可人工 `closed` 并留说明；
- 逾期：`status IN ('open','submitted') AND due_at < NOW()`，列表与看板实时计算；
- 配置：`RECTIFY_DUE_DAYS`（默认 3 天）。

## 4. 审计哈希链

### 4.1 写入

每次 `audit()`：

1. 事务内确保 `audit_chain` 单行存在，`SELECT last_hash ... FOR UPDATE`；
2. `hash = sha256(prev_hash + "\n" + 规范化字段)`；
3. 写 `audit_logs(prev_hash, hash, created_at)`；
4. 更新链头 `last_id / last_hash`；
5. 提交。

参与哈希的字段固定为：`user_id / user_name / action / target_type / target_id / detail / ip / created_at`。

### 4.2 校验与运维

- `GET /logs/verify`：按 id 升序全量重算，逐条比对 `prev_hash` 与 `hash`，再比对链头；
- 返回 `{ ok, checked, total, lastHash, head, brokenId?, reason? }`；
- `GET /logs/export.csv` 导出带哈希的审计 CSV；
- 清洗历史数据/迁移后执行 `npm run audit:rebuild` 重建整条链；
- 数据库层仍可被高权限直接改库，因此生产环境应同时开启数据库审计、最小权限账号、备份与异地日志。

## 5. 登录与会话安全

| 项 | 实现 |
| --- | --- |
| 密码策略 | 8-64 位、字母+数字、不含登录名、弱口令拦截 |
| 登录锁定 | 连续 5 次失败锁 15 分钟（可配），管理员可解锁 |
| 登录失败留痕 | `login.fail` / `login.locked` 写审计链 |
| 会话失效 | JWT 携带 `tv`，与 `users.token_version` 比对；改密/重置/强制下线后旧 token 401 |
| 改密 | 校验旧密码 + 新密码策略，换发新 token，其他设备立即失效 |
| 权限 | 复核/审计日志仅 quality/admin；临床医师只能看本人病历、本人任务 |

## 6. 部署清单

```bash
# 1. 升级数据库（不丢数据）
cd server
npm ci
npm run db:migrate

# 2. 如清洗过历史日志，重建审计链
npm run audit:rebuild

# 3. 构建前端 + 重启
cd ../web && npm run build
cd ../server && npm start
```

必须配置：

```ini
JWT_SECRET=<32 位以上随机值>
DB_PASSWORD=<强密码>
DEEPSEEK_API_KEY=<按需>
RECTIFY_DUE_DAYS=3
LOGIN_MAX_ATTEMPTS=5
LOGIN_LOCK_MINUTES=15
```

上线前检查：

- [ ] 使用独立数据库账号（仅本库 DML/DDL 权限），不要用 root；
- [ ] 8801/3306 只监听 127.0.0.1，外层 Nginx/Cloudflare 做 HTTPS；
- [ ] 关闭演示账号或改强密码；
- [ ] 配置数据库每日备份 + 备份恢复演练；
- [ ] 审计日志异地留存（数据库审计/日志平台）；
- [ ] 真实病历脱敏后再进入测试环境；
- [ ] 质控规则、评分阈值、AI 提示词由质控科与临床专家签字确认；
- [ ] 完成等保/数据安全评估与临床 UAT。

## 7. 仍然不能靠代码单独解决的事

1. **HIS/EMR 对接**：本项目提供 CSV 导入/导出与 REST API，但真实医院需要 HL7/FHIR、视图库或集成平台对接，涉及接口规范、网络策略、主数据映射；
2. **合规**：等保、数据安全法、个人信息保护、医疗AI相关要求，需要机构层面评估与备案；
3. **术语与编码**：ICD-10/ICD-9-CM-3、手术操作、药品字典需要医院主数据；
4. **临床验证**：规则阈值与 AI 提示词必须用真实脱敏病历做一致性/召回率评估，不能只看演示；
5. **高可用**：批量质控是单进程内存队列，生产建议换消息队列 + 多实例；审计链写入是单行锁，高并发下需评估吞吐；
6. **数据脱敏与授权**：患者姓名、病案号、身份证、手机号在展示/导出/日志中的脱敏策略需要按院方制度落地；
7. **责任制度**：AI 辅助不替代医师责任，需有制度文件、培训与复核签字流程。
