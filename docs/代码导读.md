# 代码导读 · 从一行 SQL 到一次 AI 质控

这份文档按「一次真实请求的流转顺序」讲代码：从建表 → 后端接口 → AI 引擎 → 前端页面。
每一步都标出文件路径和关键代码，建议对照源码看。

---

## 第 0 步：先看全景

用户在「病历质控」页点了一下 **AI 质控**，背后发生的事：

```
浏览器                    后端                          数据库 / 大模型
  │  POST /api/records/34/qc
  ├────────────────────────▶ requireAuth（校验 JWT）
  │                          ├─ SELECT medical_records WHERE id=34
  │                          ├─ evaluateRecord(record)
  │                          │    ├─ getRules() 读启停/权重
  │                          │    ├─ runQC(record) → DeepSeek / localQC()
  │                          │    ├─ INSERT qc_reports（含 prev_score / score_delta）
  │                          │    └─ INSERT record_versions（版本快照）
  │                          ├─ UPDATE medical_records SET status
  │                          └─ INSERT audit_logs
  │  ◀──────────────────────  { code:0, data:{ score, issues, version, ... } }
  ├─ QCPanel 渲染评分环 / 问题清单
```

## 第 1 步：建库建表 —— `server/sql/schema.sql`

一共 20 张表。核心是「患者 → 就诊 → 病历 → 质控报告」四层，加规则、AI 会话、日志、整改任务、审计链，以及支撑整改闭环的版本表与批量任务表。

```sql
CREATE TABLE medical_records (
  id               BIGINT      NOT NULL AUTO_INCREMENT,
  visit_id         BIGINT      NOT NULL,
  patient_id       BIGINT      NOT NULL,
  doctor_id        BIGINT      DEFAULT NULL,
  chief_complaint  TEXT        COMMENT '主诉',
  present_illness  TEXT        COMMENT '现病史',
  ...
  status           VARCHAR(20) NOT NULL DEFAULT 'draft'
                   COMMENT 'draft/submitted/qc_passed/qc_failed',
  created_at       DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at       DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  CONSTRAINT fk_record_visit FOREIGN KEY (visit_id) REFERENCES visits (id)
) ENGINE=InnoDB COMMENT='电子病历';
```

质控结果单独一张表，`issues` 用 JSON 列存，前端拿到就能直接渲染，不用再做关联：

```sql
CREATE TABLE qc_reports (
  id          BIGINT       NOT NULL AUTO_INCREMENT,
  record_id   BIGINT       NOT NULL,
  score       DECIMAL(5,1) NOT NULL DEFAULT 0,
  level       VARCHAR(10)  NOT NULL DEFAULT 'C',
  dim_completeness DECIMAL(5,1) NOT NULL DEFAULT 0,
  ...
  issues      JSON         COMMENT '问题清单 [{rule,severity,field,message,suggestion}]',
  suggestions JSON         COMMENT '改进建议 [string]',
  model       VARCHAR(50)  DEFAULT NULL,
  duration_ms INT          DEFAULT NULL,
  PRIMARY KEY (id),
  KEY idx_qc_record (record_id),
  CONSTRAINT fk_qc_record FOREIGN KEY (record_id) REFERENCES medical_records (id)
) ENGINE=InnoDB COMMENT='病历质控报告';
```

执行入口是 `server/scripts/init-db.js`，它读 SQL 文件、用 `multipleStatements: true` 一次性执行：

```js
const schema = await fs.readFile(path.join(sqlDir, 'schema.sql'), 'utf8');
await conn.query(schema);
```

## 第 2 步：数据访问层 —— `server/src/db.js`

全项目只有这一处创建连接池，其余文件都从这里 import，避免连接泄漏：

```js
export const pool = mysql.createPool({
  host: process.env.DB_HOST, port: Number(process.env.DB_PORT),
  user: process.env.DB_USER, password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  waitForConnections: true, connectionLimit: 10, charset: 'utf8mb4',
});

export async function query(sql, params = []) {
  const [rows] = await pool.query(sql, params);
  return rows;
}

export async function one(sql, params = []) {
  const rows = await query(sql, params);
  return rows[0] || null;
}
```

> 约定：所有 SQL 一律用 `?` 占位符，`query(sql, [a, b])` 这种写法，不做字符串拼接，从根上防注入。

## 第 3 步：登录与鉴权 —— `routes/auth.js` + `middleware/auth.js`

登录就是「查用户 → 比对 bcrypt 密码 → 签 JWT」：

```js
const user = await one('SELECT * FROM users WHERE username = ?', [username]);
if (!user || !(await bcrypt.compare(password, user.password))) {
  return res.status(401).json({ code: 401, message: '用户名或密码错误' });
}
const token = signToken(user);   // jwt.sign({ uid, username, role, name })
res.json({ code: 0, data: { token, user } });
```

每个受保护的路由文件顶部一行 `router.use(requireAuth)` 即可：

```js
export async function requireAuth(req, res, next) {
  const token = (req.headers.authorization || '').replace('Bearer ', '');
  const payload = jwt.verify(token, config.jwtSecret);
  const user = await one('SELECT id, username, name, role ... FROM users WHERE id = ?', [payload.uid]);
  if (!user || user.status !== 1) return res.status(401).json({ code: 401, message: '账号不存在或已停用' });
  req.user = user;
  next();
}
```

角色控制再包一层，例如用户管理只允许 admin：

```js
userRouter.get('/', requireRole('admin'), async (_req, res) => { ... });
```

## 第 4 步：病历接口 + AI 质控 —— `routes/records.js`

这是最核心的一个接口，四件事：取病历 → 调 AI → 落库 → 改状态。

```js
router.post('/:id/qc', async (req, res) => {
  const record = await one('SELECT * FROM medical_records WHERE id = ?', [req.params.id]);
  if (!record) return res.status(404).json({ code: 404, message: '病历不存在' });

  const report = await runQC(record);          // ← 第 5 步展开

  const r = await query(
    `INSERT INTO qc_reports
     (record_id, score, level, dim_completeness, dim_accuracy, dim_logic, dim_terminology,
      risk, issues, suggestions, summary, model, duration_ms)
     VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)`,
    [record.id, report.score, report.level,
     report.dimensions.completeness, report.dimensions.accuracy,
     report.dimensions.logic, report.dimensions.terminology,
     report.risk, JSON.stringify(report.issues), JSON.stringify(report.suggestions),
     report.summary, report.model, report.durationMs],
  );

  const nextStatus = report.score >= 80 ? 'qc_passed' : 'qc_failed';
  await query('UPDATE medical_records SET status = ? WHERE id = ?', [nextStatus, record.id]);
  await audit(req, 'record.qc', 'record', record.id, `AI 质控得分 ${report.score}（${report.level}级）`);

  res.json({ code: 0, data: { reportId: r.insertId, recordId: record.id, ...report, status: nextStatus } });
});
```

注意 `audit()` 是「审计留痕」，写日志失败不会影响主流程（内部 try/catch），符合医疗系统「业务优先、日志兜底」的常见要求。

## 第 5 步：AI 双引擎 —— `src/ai/local.js` + `src/ai/index.js`

### 5.1 规则引擎怎么打分（`local.js`）

先逐字段检查完整性，缺「主诉 / 现病史 / 诊断」扣 35 分，缺其他扣 18 分：

```js
for (const f of FIELDS) {
  const value = text(record[f.key]);
  if (!value) {
    const critical = ['chief_complaint', 'present_illness', 'diagnosis'].includes(f.key);
    dims.completeness -= critical ? 35 : 18;
    issues.push(issue(`C-${f.key.toUpperCase()}`, `${f.label}缺失`,
      critical ? 'critical' : 'major', f.key,
      `${f.label}未填写，属于必填项`, `请补充${f.label}相关内容，保证病历要素完整`));
  }
}
```

再做逻辑一致性校验（最值钱的一段）：主诉里的症状必须出现在现病史里，现病史必须有时间要素：

```js
const hits = ABNORMAL_HINT.filter((w) => cc.includes(w));       // 主诉里的症状词
const missing = hits.filter((w) => !pi.includes(w));            // 现病史没提到
if (missing.length) {
  dims.logic -= 12;
  issues.push(issue('L-001', '主诉与现病史不一致', 'major', 'present_illness',
    `主诉中的「${missing.join('、')}」在现病史中未描述`,
    '现病史需围绕主诉展开，说明起病时间、诱因、演变过程'));
}
if (!/[0-9一二三四五六七八九十]+\s*(天|日|周|月|年|小时|分钟)/.test(pi)) {
  dims.logic -= 8;
  issues.push(issue('L-002', '现病史缺少时间要素', 'major', 'present_illness',
    '现病史未描述病程时间', '补充起病时间与病程（如“3 天前”“反复 2 月余”）'));
}
```

最后按权重汇总，并做「严重问题封顶」，避免一份缺现病史的病历还能拿 92 分：

```js
const weights = { completeness: 0.4, accuracy: 0.3, logic: 0.2, terminology: 0.1 };
const base = Object.entries(weights).reduce((sum, [k, w]) => sum + dimensions[k] * w, 0);

let score = base - criticalCount * 8 - majorCount * 3 - minorCount * 1;
if (criticalCount > 0) score = Math.min(score, 72);   // 有严重问题，最高 72 分
if (majorCount >= 3)   score = Math.min(score, 86);
```

### 5.2 大模型模式（`index.js`）

有 Key 就把病历拼成提示词，强制模型只输出 JSON：

```js
const text = await callDeepSeek(
  [{ role: 'system', content: QC_SYSTEM },        // “你是三甲医院病案质控专家，只输出 JSON…”
   { role: 'user', content: userContent }],       // 七个字段拼成的病历
  { json: true },                                 // response_format: json_object
);
const result = normalizeQC(parseJSON(text), fallback);
```

`normalizeQC()` 会做三件事：字段兜底（模型漏字段就用规则引擎结果补）、数值钳制（分数强制 0–100）、问题数量截断（最多 20 条）。

调用失败怎么办？降级，不让用户看到报错：

```js
try {
  const text = await callDeepSeek(...);
  return { ...normalizeQC(parseJSON(text), fallback), model: config.deepseek.model };
} catch (err) {
  console.warn('[ai] 质控调用失败，降级规则引擎:', err.message);
  return { ...fallback, model: 'rule-engine(fallback)' };   // 前端会显示这个来源
}
```

超时控制用 `AbortController`，45 秒没回来直接放弃：

```js
const controller = new AbortController();
const timer = setTimeout(() => controller.abort(), 45_000);
...
fetch(url, { ..., signal: controller.signal });
```

## 第 6 步：看板聚合 —— `routes/dashboard.js`

趋势图用「日期序列 LEFT JOIN 统计」一次查完，避免前端循环请求：

```sql
SELECT DATE_FORMAT(d.day, '%m-%d') AS date,
       (SELECT COUNT(*) FROM medical_records r WHERE DATE(r.created_at) = d.day) AS records,
       (SELECT ROUND(AVG(q.score),1) FROM qc_reports q WHERE DATE(q.created_at) = d.day) AS avgScore,
       (SELECT COUNT(*) FROM diagnosis_sessions s WHERE DATE(s.created_at) = d.day) AS aiCalls
FROM (SELECT DATE_SUB(CURDATE(), INTERVAL seq DAY) AS day FROM (...0~29...) t WHERE seq < ?) d
ORDER BY d.day
```

问题类型分布则是在 Node 侧解析 JSON 再聚合（SQL 里拆 JSON 不划算）：

```js
for (const row of rows) {
  const issues = typeof row.issues === 'string' ? JSON.parse(row.issues) : row.issues;
  for (const it of issues) counter.set(it.rule, (counter.get(it.rule) || 0) + 1);
}
```

## 第 9 步：页面组件 —— 以 `RecordsView.vue` 为例

一次操作的完整链路：

```ts
async function runQC(row: any) {
  qcLoadingId.value = row.id;                 // 只让这一行转圈
  try {
    const report = await api.runQC(row.id);   // 调接口
    qcResult.value = report;                  // 塞给弹窗
    qcVisible.value = true;
    ElMessage.success(`质控完成：${report.score} 分（${report.level} 级）`);
    load();                                   // 刷新列表里的评分列
  } finally {
    qcLoadingId.value = null;
  }
}
```

报告渲染抽成了独立组件 `components/QCPanel.vue`，列表弹窗和详情页共用同一个组件，保证两边展示一致：

```vue
<div class="dims">
  <div v-for="d in dimList" :key="d.key" class="dim">
    <span>{{ d.label }}</span>
    <el-progress :percentage="d.value" :color="barColor(d.value)" :show-text="false" />
  </div>
</div>
```

图表在 `DashboardView.vue` 里用 ECharts，注意实例复用，否则点刷新会不断新建 canvas：

```ts
const chartMap = new Map<HTMLElement, echarts.ECharts>();
function getChart(el?: HTMLElement) {
  if (!el) return undefined;
  let c = chartMap.get(el);
  if (!c) { c = echarts.init(el); chartMap.set(el, c); charts.push(c); }
  return c;
}
```

## 附：一次改动的完整闭环（建议练习）

1. 想加「按评分区间筛选病历」：先在 `routes/records.js` 的 `GET /` 里加 `minScore/maxScore` 条件；
2. 在 `web/src/api/index.ts` 的 `records()` 参数类型里补字段；
3. 在 `RecordsView.vue` 的 `.toolbar` 加一个 `el-select`；
4. 重启后端，浏览器点一遍，确认筛选生效。

整条链路的约定都写在 `.trae/rules/project-rules.md` 里，Trae 会自动读取，所以你在 IDE 里直接说「加个按评分筛选」它也会按同样的分层改。
